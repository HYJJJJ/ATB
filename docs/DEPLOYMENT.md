# ATB 服务部署

本文是通用模板，不包含任何真实服务器资料。管理实际服务器前，应在本机建立不提交的 `docs/SERVER.md`，登记目标主机、固定 SSH 指纹、凭据引用、当前服务、端口、备份和恢复步骤。每次连接、部署或修改前完整读取该档案；修改后记录实际验证结果。

建议 Ubuntu 22.04+、Node 22+、独立无登录服务账户。2 vCPU / 2 GB 可用于早期信令和转发，实际容量取决于并发、视频码率、带宽及流量额度。云端不默认安装人物检测和语音模型。

1. 在受限数据目录初始化管理员。公网模式禁止从未初始化的远程页面创建首个管理员。
2. 为 `certs` 和 `data` 选择长期目录，程序使用独立版本目录与 current 符号链接。保留旧版本和敏感数据备份。
3. 参考 `deploy/server.env.example` 配置实例地址、HTTPS 端口、PUBLIC_ORIGIN、TURN_PUBLIC_PORT、DATA_DIR 和 CERT_DIR。示例的 192.0.2.10 仅用于文档，必须替换。PUBLIC_ORIGIN 当前仅接受 HTTPS IPv4 地址。
4. 摄像头云端最小依赖见 `deploy/package.json`。纯平台只需 node-forge；安装模块所需运行时见各自 package.json。通过 `DETECTION_ENABLED=0` 禁用云端模型，保留本机计算接入。
5. `deploy/freecamera.service` 是兼容既有部署路径的 systemd 模板，按实际主机修改；环境文件只读给 root、数据仅允许服务用户访问。不要把程序依赖设为只有 root 可读。
6. IPv4/NAT 模式需区分公网端口与实例监听。网页、媒体中继分别登记，先验证 TLS 和未登录保护，再验证真实视频帧增长。

首次私有 CA 信任需要在访问设备安装公开 ca.crt；禁止分享 CA 私钥。替换服务版本时不更换已受信的 CA，不覆盖已有账户和设备身份。手机旧摄像头 URL 与信令协议在模块迁移后保持兼容。

RustDesk 的安装和 systemd 生命周期见 `modules/rustdesk/deploy/README.md`。被控电脑的安全密码及授权由官方客户端管理。

升级须先验证代码/依赖，备份当前指向与配置，原子切换 current，重启并检查；失败立即切回旧版本。回滚程序通常保留新业务数据；不要盲目恢复旧账户或删除唯一备份。TCP 连通、UDP 注册和完整远控是不同的验收项目，分别记录。
