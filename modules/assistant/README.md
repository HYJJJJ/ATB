# ATB Assistant

桌面小助手使用原创鲸鱼娘 SVG，沿用 ATB 深灰蓝主题。源码桌面启动后显示透明置顶摆件，可拖动位置；点击开始/结束现有语音对话，右键打开助手、角色、语音、人脸和平台设置。主界面关闭后收进系统托盘，从托盘“退出 ATB”才能完全退出。前台语音与摆件使用互斥租约，真实语音状态、音量和流式回复可以同步到摆件。

在“平台设置 → 通用 → 桌面小助手”设置显隐、回复文字、余额/天气/新闻/使用提示。信息气泡在形象周围随机位置出现，随机间隔4–9分钟，每条只显示简短标题及两行摘要，3.5–5秒内缓慢上浮并淡出；无关闭按钮、来源按钮或滚动框，也不截获鼠标点击。开始倾听、输入或输出文字时，当前提醒约180毫秒淡出，显示对话文字期间不再弹提醒；免打扰或图片查看期间也跳过。提醒不朗读，也不调用对话模型。天气需手动搜索并选择城市，不自动定位；天气来自 Open-Meteo，网络不可用时使用 wttr.in / WWO，新闻来自中国新闻网 RSS，并非今日头条专用接口。数据源保留来源与时间，提醒仅展示短摘要，详细来源可在正常工具对话中查看；取不到则跳过，不生成假信息。余额复用现有查询能力。回复中的图片由用户点击后才加载，支持公网 HTTPS 的 PNG/JPEG/WebP、最大2MB，可在主题窗口放大。

桌面工作台启动或重新载入时，只将最近主动消息恢复到对话记录，不在主窗口右下角重播旧消息，也不重新朗读；新产生的主动消息由后台送到小人物回复气泡，并按语音总开关播放。

停止或打断语音会取消本轮等待中的合成与音频读取；桌面IPC将其明确标为取消，不再作为“语音已停止”的接口异常打印，也不视为播放成功。查询或合成真正失败时，先停止失败回合，再在人物周围显示原始错误短提示，已显示的回复气泡让出位置；后续可重新开始对话。授权、网络与超时错误仍正常报错，不会自动重试付费请求。仅凭取消栈不能判断此前新闻查询的上游失败原因。

在线长回复的音频接收现在跟随播放进度：待取PCM仍限制1MiB，满时等待读取腾出空间；HTTP暂停继续读取，WebSocket暂停接收并按顺序处理音频和完成事件。此前上游生成较快时会冲满队列，中断并误报通用连接错误。停止会唤醒等待中的写入并丢弃旧音频；不自动重试付费请求，单次音频6MiB、响应10MiB和合成超时限制保留。`node modules/assistant/scripts/test-volcengine-stream-ui.js --long`（桌面加`--desktop`）使用本地协议夹具与真实Web Audio验证四种方式各1.5MiB音频完整播放，不调用付费接口。

摆件设置保存在数据根目录 `data/platform/desktop-companion.json`，重启恢复位置及提醒计划。注销清空旧回复并硬释放摆件语音；普通暂停仍按原策略保留模型。新增主进程修复后须从托盘完全退出，再运行 `Start-ATB-Desktop.cmd`。隔离桌面检查不替代用户实体麦克风、扬声器或付费供应商验收；本轮没有生成发行包。

显示摆件且已登录、语音总开关已开启时，会自动提前加载 SenseVoice 识别及**当前选中的** ChatTTS / Qwen3-TTS 合成模型；使用火山语音时只预载本地识别，不请求付费合成。预加载不打开麦克风、不占用持续对话租约；点击时复用同一模型进程，加载尚未结束则等待同一次初始化。普通暂停保留模型，隐藏摆件、注销、停用语音或退出回收其持有的资源；其他入口正在对话时不抢占。切换厂商后按新选择准备，加载失败显示悬停提示并有一分钟重试间隔。倾听时抬手靠耳并侧头，回答/停止时恢复，减少动态效果下仍有明确静态姿势。预加载本身不收麦；下面的唤醒开关另行控制待机监听。可运行 `node modules/assistant/scripts/test-voice-preload.js`，使用隔离设置检查两个已安装本地模型的预载、复用、静音识别、固定文字合成与释放。


在“智能助手 → TTS 与语音 → 语音唤醒”开启待机唤醒（默认开启，仍遵守语音总开关）。默认唤醒词是当前已保存的助手名称，切换角色后自动更新；自定义短语每行一句、2–40字、最多12条，沿用底部“保存全部语音设置”。已登录、桌面小助手可见且对话模型可用时，待机在本机用SenseVoice处理短句；无关语音不保存、不进入对话或记忆，不调用付费对话/语音API。悬停人物可看到“等待唤醒：名字（麦克风本地监听中）”。这是本地短句识别后匹配，需短暂停顿，不是专用的低功耗关键词检测模型，也没有说话人身份校验。

说“小鲸鱼”会先听到一句简短应答，再开启语音倾听；也可说“小鲸鱼，今天天气怎么样”，先应答，再去掉开头称呼后只发送后面的请求。仅匹配句首（可带嗨/你好等称呼），支持中文同音、不区分声调及常见前后鼻音误识别，例如SenseVoice实测“小鲸鱼”识别为“小金鱼”仍能命中。短中文名字以“小”开头且余下2–4字时，也可直接叫剩余昵称：“小鲸鱼”可叫“鲸鱼／金鱼”，切换角色后旧昵称失效；不缩短自定义短语、不自动匹配单字昵称。句中提到“我家的金鱼”不会唤醒；不做任意删字或模糊文本匹配。姓名多音字或识别偏差较大时可加自定义别名。英文短语忽略大小写并保留词边界。命中先释放待机麦克风/租约，再复用同一模型开启正式对话；主界面消息/语音、试听及后台问候取得语音时暂停待机，避免自身朗读触发。普通对话停止后恢复待机；关闭唤醒开关停止待机收麦，点击人物仍可开始语音；隐藏、注销或退出清理。外放/电视中有人以同样称呼开头也可能触发，实际麦克风与扬声器环境仍需测试。

唤醒应答根据当前已保存角色的性格、口头禅和说话习惯，由所选对话模型提前准备数句短句（每句最多20字），随机轮换且避免紧邻重复；使用当前音色和输出设备，人物同步说话状态，文字遵守摆件的显示开关。只叫名字时应答后等你继续说，同句有问题则应答后处理一次。应答播放排空后才开对话麦克风，避免把自身应答识别成用户讲话；途中点击关闭、隐藏或注销取消播放，不会迟到开麦。手动点击开始对话沿用直接倾听。

短句准备仅在已登录、摆件显示、语音与唤醒开启且模型可用时发生，通过认证同源的 `POST /api/assistant/wake-replies`，只使用当前角色提示，不发送历史或日记、没有工具权限、不生成聊天或记忆。成功结果按账户及角色/模型配置缓存在本次服务进程内，切换角色或配置后重新准备；每次唤醒不额外请求对话模型。准备会消耗少量所选对话API额度，语音合成仍按原所选服务计费；准备未完成或失败时先说中性的“我在，你说”，失败至少一分钟后才重试。合成/播放失败会显示实际错误，不用无声动画代替应答成功。模型的实际人设遵循度和物理扬声器听感仍需用户测试。

语音唤醒的拼音转换使用固定pinyin-pro 3.28.1（MIT）本地浏览器资源，不依赖CDN；许可及npm归档完整性/SHA256见`docs/licenses/pinyin-pro/`。`node modules/assistant/scripts/test-wake-local.js`用隔离设置、真实ChatTTS合成固定测试句并用SenseVoice回读，检查名字/自定义/非唤醒短句及同进程交接，不使用实体麦克风或付费API。可加`--probe-short`重现极短称呼诊断：固定合成“鲸鱼，现在几点？”曾两次被SenseVoice读成“基于现在几点”，会漏唤醒；该探针按失败报告，不把“基于”自动当作唤醒词。读音容错不能补回ASR已经丢失的音节或声母，实体发音及环境仍待实测。

语音对话中说“下去／退下吧／晚安／别说话了／结束对话／先不聊了／拜拜”等直接收尾语，本轮回复播放完毕就结束对话、释放对话麦克风，不再自动继续聆听。此规则共用于主界面、桌面小人物和后台问候接续；不修改已保存的自动聆听设置，之后仍可点击或用唤醒词重新开启。“晚安是什么意思”“不要结束对话”或转述别人说晚安不触发结束；只判断本轮用户输入，不判断助手回复或试听文字。“先别打扰我”仍单独立即暂停主动互动两小时；普通告别不设置长期免打扰。启用待机唤醒时，结束正式对话后仍按原开关恢复本地唤醒监听。

“余额提醒”同时涵盖当前对话 API 的近24小时消耗，与余额提示交替出现。支持 New API 只读密钥日志时，通过固定同源 Bearer `/api/log/token` 读取有界最近记录，只汇总滚动24小时内的消费并扣除退款，充值/错误不计入；结果属于当前密钥，不是整个账户。日志仅覆盖最近一段时显示“近24小时已查消费”，有退款时标“净消费”；空记录、未开放接口、未知币种不会冒充零消费。读取沿用公网HTTPS、无重定向/URL密钥、超时及响应上限，缓存一分钟，`GET /api/assistant/usage?refresh=1` 可强制刷新；登录失效或 API 切换不返回迟到的旧结果。

DeepSeek 等没有上述消费明细的接口，使用本地账户余额观察兜底，明确显示“近24h余额减少估算”和实际已记录时长。首次显示“消费统计积累中”，从启用后开始记录，不能补回启用前的24小时；充值/退款与消费发生在同一采样间隔时可能掩盖消费，不能把估算当实账或单密钥开销。小组件启用提醒且勾选余额时，每分钟静默采样一次；助手主界面已有余额刷新也记录，软件关闭期间不补采样。仅保存余额点，按地址/密钥哈希分组、币种/范围变更重置，有界保留最近24小时及一个边界点；文件为数据根目录 `assistant/balance-history.json`，无密钥或原始消费日志。此项目前针对对话 API，语音仍展示原有余额/本地免费状态，不推算未知币种的火山消费。

The assistant module owns chat, model settings, persona, automatic account-shared three-layer memory, and optional local speech recognition with selectable local/cloud synthesis. Its public entry is /modules/assistant/ and its authenticated HTTP routes retain /api/assistant/*.

The **TTS 与语音** page has one fixed bottom action bar: **保存全部语音设置**, voice preview/stop, device/status refresh and greeting preview. Saving validates both sections first, then persists TTS parameters, arrival/greeting policy, camera/output selection and any changed daily self-report. A failed section is identified and its draft remains unsaved; edits made during saving are retained. Device refresh preserves draft selections. Greeting preview reads the current local greeting template with enabled date/context values; it does not test face recognition. Device/status refresh re-enumerates camera/output choices and refreshes voice/background status. Background presence controls require the desktop app. Shared checkbox/radio captions fit their content, and unfocused input/textarea/select elements pass wheel scrolling to the surrounding page; focused textarea boundaries remain contained.

The platform provides AccountStore, SharedSettings, and the data directory through docs/MODULES.md. Node 22+ and the module-owned `ws` dependency provide HTTP and WebSocket synthesis adapters. The optional voice setup installs pinned Python packages and verified model files; it does not move an existing Python environment.

From the ATB installation directory, run:

```text
python modules/assistant/scripts/setup-assistant-voice.py
```

Use --data-dir to select the existing data/assistant directory explicitly. ATB_DATA_DIR and FREECAMERA_DATA_DIR are also supported as installation data roots. The worker and setup script are module-owned; Python, downloaded models, voice settings, persona, and memory remain under the platform data directory.

For optional local synthesis, run `python modules/assistant/scripts/setup-local-tts.py` with Python 3.10–3.12, then choose **本地 · ChatTTS** or **本地 · Qwen3-TTS 0.6B** and save. `--mirror` uses the Hugging Face mirror; `--cpu` installs CPU PyTorch. ChatTTS installs into a dedicated `tts-runtime` with PyTorch 2.8.0/cu128 on Windows, transformers 4.44.2, and ChatTTS 0.2.5. Qwen3-TTS uses `qwen-tts-runtime`, sharing CUDA libraries read-only while pinning qwen-tts 0.1.1 / transformers 4.57.3 independently. `--provider qwen3tts --mirror --modelscope` installs just the Qwen weights (the common CUDA environment is still prepared if absent); all bytes must match the fixed manifest SHA256. SHA256-pinned assets occupy approximately 3.5 GiB, in addition to Python/CUDA dependencies. GPU is preferred automatically, with CPU fallback. ChatTTS includes all 2646 saved speaker embeddings from the reviewed ChatTTS_Speaker snapshot, sorted by single-sentence stability by default, with multi-sentence/long-sentence sorting available. Each option shows seed ID, Gender, Age and stability score. These are estimated labels and stability scores, not voice quality ratings. This sampled library is not all possible voices; four random-seed shortcuts and any uint32 seed (0–4294967295) remain available. Qwen CustomVoice exposes all 9 speakers from its config, verified against get_supported_speakers(), and Auto plus all 10 languages returned by get_supported_languages(). Language filters are generated from provider/model metadata and cloud voice locales, not fixed UI buckets. Search names/languages/IDs inside the themed voice dropdown; filtering preserves the selected voice, supports keyboard selection, and reports empty results. Rate -50…100%, volume -100…100%, pitch fixed at zero. The selected model loads on first use and stays resident between previews, read-alouds and paused conversations. Voice/rate/volume changes reuse the same model. Disabling an enabled voice feature, switching provider, logout, desktop module suspension and application shutdown unload it. Microphone-disabled preview settings can be saved without unloading TTS. Only one selected local model stays loaded. A synthesis-only worker can add recognition lazily when conversation starts, without reloading TTS. Playback stops immediately; an inference already running is drained with its results discarded before the next job, bounded by the request timeout. Model reuse avoids repeated loading; streaming behavior is described below. F5-TTS, Edge and ZipVoice are removed. Old F5/Edge/Kokoro/ZipVoice selections migrate on read to the saved ChatTTS profile, or random seed 42 if no ChatTTS profile exists, without rewriting private settings. Model licenses differ from code licenses; see `docs/LOCAL-TTS-LICENSES.md`.

ChatTTS defaults to the **回复音色** preset dropdown, with a **自定义** button on its right. This switches to **回复音色（自定义随机种子）** and a number input; **预设** restores the dropdown. Both choices are retained while switching, including between providers. Reload defaults to the dropdown without changing the saved voice. Hidden custom drafts cannot block preset saving. Seed edits immediately select the new voice and mark settings unsaved; save before preview. Ranked IDs (`chattts:speaker:seed_N`) use the original saved embedding; random IDs (`chattts:N`) retain their previous sampling behavior. The same number need not sound the same across environments, so these identities stay separate. The four unranked dropdown seeds are shortcuts, not the total voice count. Valid IDs are integers 0–4294967295; different IDs are not a guarantee of distinct or equally usable voices. Preview now separates reading settings, loading the model, generating the first audio chunk and playback. ChatTTS streaming keeps two decoded batches ahead of playback to avoid exposing the unstable tail of each growing-prefix decode. The playback cursor still begins at sample zero: this is a short startup buffer, not discarded opening audio. The previous pass_first_n_batches=0 optimization caused periodic splice buzz and has been reverted. Normalizer machine code is cached under `assistant/cache/chattts-numba` (or `NUMBA_CACHE_DIR` when explicitly configured) across worker restarts; cold model loading and first CUDA inference still take time. PCM completion waits for the output device timeline or reported device latency before closing, and stop cancels this wait. ChatTTS alone retains the final 8 ms across network packets, applies a cosine release once when the entire reply finishes, then schedules 220 ms of silence before draining the device. This preserves speech sample count and avoids a hard nonzero waveform ending; it does not insert a pause or fade between packets or sentences. Manual stop discards the retained ending and cancels immediately. With skip_refine_text enabled, native ChatTTS now receives a terminal [uv_break] prosody token (idempotently) for both PCM streaming and WAV synthesis. The reported seed_1244 preview previously ended with active final-vowel energy; padding or a fade after generation could not restore that vowel. The built-in token lets the model generate its own release before EOS without adding spoken words, enabling text refinement, or switching voices. Restart the synthesis worker/application to load this Python change; a page reload alone keeps the old resident worker. The optional real-model regression `scripts/test-chattts-ending.py` measures native final-60-ms energy for the reported sentence across three voices and a long ending; ASR text alone is insufficient to certify phoneme completeness.

Saved role tags appear under the **助手设定** heading, above **助手名称**. Saving a name and role description creates a persistent preset; saving the same name updates it, while a new name adds a tag (up to 100). Click a tag to apply its name and prompt immediately. Existing unsaved assistant settings require the shared themed discard confirmation. Hover or keyboard focus reveals its top-right delete button; touch devices show it directly. Removing a preset leaves the currently applied role and other settings intact. Existing saved roles are recognized on load without writing private settings merely to migrate them. Presets share the existing installation-wide persona settings; API configuration, memory, conversation style and proactive permissions remain independent.

Conversation style lives under **智能助手 → 助手设定**. Choose 简洁 / 自然 / 健谈, enable optional follow-up questions, and save. Natural is the default and encourages 2–4 sentences; talkative encourages 4–8 with relevant examples and a 2048-token ceiling. These are model instructions, not guaranteed sentence counts; direct user requests for brevity take priority. Follow-ups are limited to one relevant question when appropriate.

**随机主动机会** replaces the old second-based idle voice trigger. Enable **助手设定 → 允许随机主动机会** and save. A durable account-private scheduler samples each next interval independently (45–90 minutes; registered game adapters use110–180 minutes), rolls probability0.55 by default, and allows at most8 successful wakes/day and2 owner messages/day. Probability0–1 and wake cap1–8 are saved settings. A missed roll does not consume a wake. Eight attempted rolls have an expected4.4 hits; the eight-wake limit is a maximum, not eight scheduled attempts or a guarantee of daily activity. Five minutes of recent dialogue and active processing defer25 minutes; existing timezone, quiet hours, self-reported busy feedback and snooze controls also apply. Existing saved quiet policy is preserved (presence defaults22:00–08:00). Equal quiet start/end means all day. The scheduler persists the next time and reservation before calling the selected API, never catches up missed opportunities in a burst, and does not reroll at startup. An interrupted reserved wake becomes a completed none result on recovery.

Each hit offers the optional “【有一会儿空】” turn with “什么都不做也行”. Only a validated native Chat/Responses opportunity_decide call can select an action; prose/DSML is never executable. No action, unavailable/malformed choice and cancellation end the current opportunity without automatic retries, follow-up prompts or error alarms. Persona, core/light memory and unexpired pending thoughts provide context; private diaries are not injected. A thought may be retained for2hours. Decisions consume the current API quota even when she remains silent. Normal user replies keep their existing streaming and memory paths; proactive choices are never synthetic user memory turns.

The authenticated assistant page, platform page and desktop background share the same schedule. Desktop background can wait while minimized, without opening a camera or microphone. If face identification is enabled, background owner conversation additionally requires a fresh confirmed self profile and its background-opportunity permission; visitors never acquire private opportunities. Foreground audio takes priority. Microphones use the existing automatic inactivity stop; enabling opportunities no longer forces continuous listening. Voice synthesis only starts for an actual chat result when synthesis is enabled. The most recent owner message has a stable persisted delivery id; the main page can recover it from a hidden renderer within24hours, deduplicating per page session. State lives at assistant/state/proactive.json under the selected data root, keyed by hashed private account ids. Bounded outcomes retain dice values, hit/miss, postponement reasons and choices; open **主动机会记录** to inspect them. No cron or fixed-time AI trigger is installed.

Currently available actions are owner chat and none. No real post-reading/search or game adapter is installed, and the assistant must not claim it browsed or played. The internal adapter boundary permits proactive reads, denies external writes without a trusted explicit owner approval callback, and aborts long operations at a maximum10minutes. Future adapters must actually honor AbortSignal to stop external work. No arbitrary external posting tool is exposed to the model.

**快速回复** is a saved setting, enabled by default. For voice conversation, Chat Completions/Responses stream visible output to the browser as authenticated NDJSON, excluding reasoning and tool events. With Volcengine WebSocket bidirectional selected, model text deltas feed one synthesis session directly, without extra sentence splitting, and PCM chunks play as they arrive. The other three Volcengine modes submit complete short sentences as separate sessions as the model writes, sharing one sequential PCM player. A sufficiently long unpunctuated first phrase also flushes after a short pause instead of waiting for model completion. At standard speed (rate 0), Qwen3-TTS submits natural short clauses while chat text is arriving, and emits PCM during audio generation. Changed speed uses complete-clause WAV synthesis, overlapping playback with preparation of at most one next clause. ChatTTS now uses its native stream=True generator: each sentence produces bounded PCM chunks through the same authenticated HTTP/IPC queue and PCM player as cloud synthesis, before the sentence finishes. ### 桌面摆件布局（2026-11-14）

倾听时抬手靠耳，识别、等待模型和准备语音时手托下巴并显示思考点。本地语音控制器活跃时忽略其他窗口迟到的状态/音量/回复；远端不同窗口停止也不覆盖当前语音所有者。回复方位一旦选定就保持，文字流和原生画布扩展不换边，只在拖动人物或显示器布局变化后重新选方向；高度仍随长文字向上延展。随机提醒限在人物头部附近采样，保留避让、上浮与自动淡出。

右键菜单支持点击菜单外（包括人物）、按 Esc 或切换到其他窗口时收起；关闭后同步恢复透明区域的鼠标穿透。Electron 原生窗口失焦通过独立事件通知菜单关闭，避免仅监听页面失焦而漏掉桌面点击。点击人物仍正常开关语音，菜单选项正常执行。此修复包含主进程代码，需从托盘完全退出并重新启动源码预览。

形象保存独立的屏幕中心坐标；透明画布随位置动态移动到所在显示器内，松手不再把形象挤回。支持负坐标多屏、旧窗口位置迁移和图片放大后保持形象位置。用户可以把形象拖至边缘甚至部分移出屏幕；启动或显示器移除时恢复可见位置。回复框避让屏幕边缘，短提醒整段上浮轨迹也避让人物和窗口边缘，放不下就跳过，轮询不重排当前提醒或重启动画。人物点击和聚焦不显示矩形蓝框；回复气泡无关闭按钮或可见滚动条，宽度最高350px，高度按当前文字、图片入口与来源自然计算，流式增加时以动画优先向上延展，保留开头与新文字。已移除300px固定上限；需要时同步扩展原生透明画布，人物屏幕坐标不变。达到实际显示器空间才用隐藏滚动条的滚轮阅读，新文字和轮询不抢阅读位置；新的一条短回复恢复自己的高度并回到开头。原生布局和窗口尺寸同步后才重新测量，避免图片预览切换时误藏长回复。朗读期间保留文字，朗读结束后5秒上浮淡出；没有朗读时从完整文字到达开始计时，轮询不延长或复活气泡，新回复取消旧轮淡出。鼠标悬停阅读或查看图片期间暂停消失计时。菜单保留统一灰蓝细滚动条，随机提醒不滚动。主动回复只展示一份。形象下方不显示状态文字条，点击形象开关语音，右键打开快捷菜单。

ChatTTS与Qwen3-TTS在送入本地语音模型前，将中文场景中的金额、小数、百分比、日期、时间和温度转换为中文读法，保留小数精度与大数数量级，验证码和手机号逐位读。聊天文字仍保留原数字，英文/日文/韩文段落、代码、网址和型号不强制改为中文。流式分句保护连续数字，避免千位逗号、长度边界或模型短暂停顿拆开小数；本地PCM在收齐同一句文本后规范化。云端沿用供应商规范化。本轮验证覆盖真实运行时请求和模拟worker接收文本，未运行实体扬声器或真实模型听感验收。
